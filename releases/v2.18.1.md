# sys-buddy v2.18.1 — 2026-09-14

Patch release. **Fixes a crash on start for every fresh install of v2.16.0 through
v2.18.0.** No behaviour change, no schema change.

## Fixed

### A fresh install no longer crashes on launch

Installing or upgrading sys-buddy recently produced an app that would not start:

```
ImportError: cannot import name 'McpError' from 'mcp.shared.exceptions'. Did you mean: 'MCPError'?
```

Nothing in sys-buddy changed to cause it. sys-buddy declared its core dependency as
`fastmcp>=2.0` — "any version from 2.0 up" — and did not name `mcp` at all. An install
does not use the project's lockfile; it takes the newest release the declaration allows.
So the day **fastmcp 4.0** and **mcp 2.0** were published, every new install picked them
up — and mcp 2.0 renamed `McpError`, which sys-buddy imports on startup.

Both are now bounded below their untested major versions (`fastmcp>=2.0,<4`,
`mcp>=1.0,<2`), so a fresh install resolves the versions sys-buddy is actually tested
against.

We pinned rather than patching around the rename. sys-buddy imports several other names
from fastmcp, so the new major almost certainly changes more than one of them, and a
shim would have claimed support for a version nobody has run. Moving to fastmcp 4 will be
its own release.

## Why the tests did not catch it

The test suite passed throughout — because it installs dependencies **from the lockfile**,
so it only ever proved that the locked versions work. Users never get those.

A new CI check, **fresh-install**, closes that gap: it builds the package and installs it
the way a user would, with no lockfile, then imports the modules that run on startup. It
was checked in both directions before release — this version passes it, and v2.18.0 fails
it with exactly the error above.

## Migration

Upgrade and relaunch:

```
uv tool upgrade sys-buddy --no-cache
```

If you are still on v2.16–v2.18 and cannot upgrade yet, reinstalling with the bounds
applied also works:

```
uv tool install sys-buddy --force --with 'fastmcp<4' --with 'mcp<2'
```

## Tests

**1809 passing**, unchanged — this release changes dependency bounds and CI, not code.
