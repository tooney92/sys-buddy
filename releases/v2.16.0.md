# sys-buddy v2.16.0 — 2026-08-18

Minor release. **A host can reissue a guest's dashboard link from the board, and an agent
whose token expired now gets told so instead of a cryptic error.** No schema change. Restart
any long-running broker so it runs the new middleware.

## Added

### Reissue a guest's dashboard link — from the dashboard, or the CLI

A viewer token is stored only **hashed**, so a guest link that gets lost cannot be read back
out. Until now, recovery meant hand-editing the database. Now the host **regenerates** one on
demand — **same seat**, a fresh token, so the guest's acceptances, signatures and message
history stay hers; only the credential is new.

- A host-only **"Guest links"** button in the dashboard header opens a modal listing the task's
  guests; **Copy link** reissues a fresh link and copies it to the clipboard, built for the
  exact origin the host is viewing on (the tunnel), so it is always the URL the guest needs.
- The same thing from the terminal: **`sys-buddy task guest-link <task> <name>`**.
- It is a **host-only** action end to end: `POST /host/guest-link` refuses any token that is not
  the host's all-tasks viewer — a buddy or a guest gets one opaque 403, so the board stays
  read-only for everyone but the host here too.

## Fixed

### An expired agent token now says so, and how to fix it

A tunnelled broker gives agent tokens a 24h TTL, and when one lapses the agent is locked out.
The broker already composed a helpful message — *"your token EXPIRED … ask your host to run
`sys-buddy task extend-tokens`"* — but it never reached the agent. Auth failures were raised as
a `ToolError`, and a `ToolError` raised during the MCP **`initialize` handshake** (which is what
a reconnect sends) gets flattened by the transport to a bare **`-32602 Invalid request
parameters`**. So the message landed only in the broker's log, and the agent saw a cryptic code
with no idea what happened or who could fix it — the exact silent failure that cost a live
session an evening.

They are raised as **`McpError`** now, whose `message` survives to the client on **every** request
type, handshake included. An agent reconnecting on an expired token now reads the whole
sentence: what happened, that it cannot fix it itself, and the one command its host runs.

### A new dashboard overlay could silently never open

`render()` is gated by a signature (`sig()`) so it only repaints when something it tracks
changes. A new overlay's open/closed state has to be registered there or the overlay never
paints — the guest-links modal above would not have opened without it. Fixed, and noted so the
next overlay does not hit the same trap.

## Migration

None — no schema, no config. **Restart any long-running broker** so it runs the new auth
middleware (the expired-token message) and serves the new page. An open dashboard just needs a
reload for the "Guest links" button.

## Tests

**1703 passing**, up from 1696.

New coverage: the host reissues a link and it resolves to the **same** seat; reissue by display
name; a non-host viewer is **403**'d; an unknown guest is **400**. And on the delivery fix: an
expired token now raises an **`McpError`** carrying `EXPIRED` and `extend-tokens`, with a guard
that the auth path never regresses to `ToolError`.
