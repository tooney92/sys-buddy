# sys-buddy v2.18.0 — 2026-09-10

Minor release. **Picking a collaboration back up the next day is now one screen instead of an
hour of archaeology — and an agent is finally told which seat it is.** One additive table
(`settings`); nothing to migrate. **Restart any long-running broker** so it serves the new
route and the new desktop app.

Every change here came out of a single bad morning. Two developers tried to resume a
day-old task and found four unrelated things had rotted overnight — and only one of them
wanted the fix everyone reached for.

## Added

### Resume a session — a diagnosis, not a button

The desktop app grows a third card, **Resume a session**. It opens your dashboard (the front
door that never existed — finding it used to mean a CLI command plus a viewer token you had
to have kept), and it health-checks any task before you pick it back up.

Every row is **probed, not assumed**, and each carries the ONE targeted fix for that row,
with the terminal equivalent beside it:

| Row | What it catches | The fix |
| --- | --- | --- |
| Broker | not running | start it |
| Public URL | tunnel rotated since last session | copy a re-point message for peers |
| Staging target | dead | set the new URL |
| Agent tokens | near expiry | extend, or lift the expiry |
| Each seat | joined / invited / unfilled | copy their dashboard link, or invite |

Why a report rather than a single button: a "resume" that revokes and re-invites is a
footgun. Press it on a healthy session and you have just kicked out a peer who was working
fine. Four of that morning's five problems needed no revoke at all.

### Reissue a BUDDY's dashboard link — without touching their seat

A guest who lost her dashboard link could always be sent a new one. A **buddy** could not,
and that asymmetry is why a perfectly healthy seat got revoked and re-paired to recover one
mislaid URL — costing that developer his agent token, his MCP config and his pre-flight.

A dashboard link is the most losable thing the broker hands out, because **the host never
holds a copy**: pairing gives it to the buddy at redeem time and nowhere else, and viewer
tokens are stored only hashed. So recovery has to be a fresh mint. Same seat, new
credential; acceptances, signatures and history stay his.

New: `sys-buddy task viewer-link <task> <who>`, `POST /host/viewer-link`, and a button on
the panel. The reissued viewer is **read-only** — a non-NULL `agent_id` is what opens the
guest write surface, so a guest is refused here and sent to `guest-link`.

### The broker tells an agent which seat it resolved them as

`rules()` now opens with **"YOU ARE @seat — the 'role' seat on task X"**, and `roster()`
marks the caller's own row.

The broker stamps an identity on every single call — it scopes by the caller and writes them
into audit events — and never once said so. An agent could read the entire cast and still
not know which row it *was*. That is how an agent whose client held another seat's token ran
a whole session believing the seat its **prompt** named, while every message and contract
signature was filed under the seat its **token** named. Nothing it could call would have told
it. Now the first tool it calls does.

### Tunnel awareness

The broker now reads ngrok's local agent API to learn its own live public URL — which works
*whoever* started ngrok, so it costs no process supervision — and remembers the previous one.
Knowing the tunnel **moved** is the fact that matters: that is the moment every peer's MCP
config silently went stale.

It also checks the tunnel forwards to the **broker's** port. One aimed elsewhere otherwise
shows up on a peer's machine as an inexplicable auth error.

### `sys-buddy task resume <task>`

The same report at a terminal. Probes; changes nothing.

## Changed

### Re-pairing a seat is now the last resort it always should have been

Revoke-and-re-invite still exists — it is the only cure when a peer has lost their **agent**
token, which lives only in their config and cannot be recovered. But it is a quiet secondary
link, never the primary button, it states its cost before it runs, and the desktop bridge
**refuses to perform it without an explicit confirm**, so it is not reachable by accident
from a panel people click through quickly. Guests are refused outright: a guest has no agent
token to lose.

## Migration

None. The new `settings` table is created on boot by the existing self-healing schema.
**Restart any long-running broker** so it serves `POST /host/viewer-link` and the new
desktop app; an open dashboard just needs a reload.

## Tests

**1809 passing**, up from 1740.

New coverage on the things most worth getting wrong: that a reissued buddy viewer is
read-only and a guest is refused; that `roster()` marks *exactly* the caller and no other
seat; that two tokens on one task each see themselves; that re-pairing refuses without a
confirm and keeps signatures; and that the fix panel has **no** revoke path at all.

One rule earned the hard way and now pinned by a test: **alive means "answered", not
"answered 200"** — a healthy API returns 404 at `/`, while a dead tunnel returns nothing.
Checking for 200 would have flagged a working backend as broken every single session.
