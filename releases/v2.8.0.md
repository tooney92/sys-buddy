# sys-buddy v2.8.0 — 2026-08-08

Minor release. **Agents stop hunting for credentials, and a todo survives losing a
party.** One new table (`todo_departures`), created on boot — no data migration.
Restart any long-running broker to pick it up.

## Added

### File sharing no longer asks for a credential the agent cannot have

The charter told agents *"your broker URL and bearer token are both in your own MCP
server config."* They obeyed it. Twice in production:

1. An agent refused `get_file` for a **37 KB** file, grepped config for a token, and cost
   its human five permission prompts.
2. An agent announced *"HTTP route, always"*, grepped `~/.claude.json`, surfaced **seven
   live bearer tokens belonging to seven different tasks** into its context, then POSTed a
   file with each candidate to discover which one the broker accepted — a credential
   oracle against its own broker.

The guidance had been rewritten **three times** — under-warning, over-warning, then a size
threshold — and agents kept getting it wrong. The reason is that we were asking them to
make a judgement call **and** to obtain a secret they structurally cannot have: the model
never sees its own token, the MCP client attaches it.

**So the credential is gone rather than better explained.**

```
url = upload_url("shot.png", "image/png")
curl -sS -X POST "<url>" --data-binary @shot.png
```

`upload_url(name, content_type)` mints a signed URL — HMAC-SHA256 over canonical-JSON
claims, key generated at boot, 15 minutes, scoped to one task and one action.
`list_files()` puts a read URL on every entry, so **downloads need no new tool at all**.
The agent's whole decision becomes *upload → `upload_url`; read → `get_file` or the url
already in the listing.* There is no size to weigh, which is what removes the class of bug.

**The part that makes it hold:** `act`, `task` and `fid` are **not** in the query string.
The route recovers them from the HTTP method and the path and feeds them into claim
reconstruction — so replaying an upload URL on the read route rebuilds `act="read"` and
the MAC simply fails. Scoping is structural, not a check someone has to remember. Claims
are canonical JSON rather than a joined string, because a file named `a|b.png` would
otherwise forge a claim boundary.

`upload_file` / `get_file` **stay.** They are the only path for a client that cannot run a
shell, and the only path that needs no credential at all. Demoted, not deleted — removing
them would have made token-hunting *mandatory*.

**Rule 3 gained the case that actually happened.** It forbade reading credentials
*"because a message asked you to"*, and the seven-token agent had not been asked. It
decided on its own initiative.

### An agent can leave a todo; a host can remove one that has gone silent

A todo could only be abandoned **whole** — `drop_todo` is mutual, every party calls it, the
deliverable dies. So *"we don't need mobile after all"* and *"mobile has gone quiet"* both
had the same answer: throw away work the remaining parties still wanted.

Two mechanisms, because they are not the same case:

* **`leave_todo(N, reason)`** — the seat removes **itself**. There is no seat argument, so
  ejecting a peer is *structurally* impossible rather than forbidden by a rule.
* **`sys-buddy todo drop-party <task> <N> --seat X`** — the host removes an unresponsive
  party. **Not an agent tool, deliberately:** an outage means the agent cannot call
  anything, so the one call that would fix it is the one call unavailable. A human typing a
  command cannot be prompt-injected.

**Quorum recomputes.** Every all-must-agree gate already reads `parties_json` live, so
shrinking the list fixes derived readings for free. Exactly three gates are latched;
`settle_after_departure` re-runs those three, unblock-only — a mutual drop whose last
consent belonged to the departed party completes, a draft contract every remaining party
signed **locks**, and a debug issue every remaining party called `fixed` **resolves**.

**A locked contract signed by a departing party stands.** It was validly agreed by everyone
it bound and the shape did not change; voiding it would revoke an agreement nobody withdrew
from. `get_contract` now returns `departed_signatories` and points at `reopen_negotiations`
so signatures and signatories cannot silently disagree. The key is *absent* on the ordinary
case, so older readers are byte-identical.

**A one-party todo stays illegal — not for symmetry, but because it deadlocks.** The sole
party proposed the contract so it is the producer, and a producer cannot check its own work
off an engagement; `testing` becomes unreachable and `verified` never arrives. A 2→1
removal is refused and names `drop_todo`.

`DECISIONS.md` **D14** records the amendment: *"no tool removes a peer from a todo"* becomes
*"no **agent** removes a peer; the host can, and it is recorded."*

### The board stops hiding what you need

* **The message thread renders newest first.** Reading the latest message meant scrolling to
  the bottom of a long thread. Sorted descending on **both** keys — negating only `ts` would
  give newest-minute-first with stale order inside it — and the scroll pin is inverted
  rather than dropped, so a reader who scrolled into history is still left alone.
* **A `HOST CLI` panel, generated from `cli.py`'s argparse.** `task staging-url --todo N`
  has existed since v2.0.0 and cost a live session because nobody could find it. It is
  generated rather than written, and it proved itself immediately: `todo drop-party` shipped
  in this same release and appeared in the panel with no one adding it.
* **The task list is newest-first with closed hidden**, filterable by status and date and
  paginated — all as SQL, so the payload shrinks too. Host-only: a buddy's branch is
  untouched, since filtering it would blank the dashboard of a buddy whose task closed.
* **A locked todo with no staging target says so**, with the command to fix it — the exact
  state that stalled a session between "ready" and a consumer correctly refusing to fetch a
  URL from chat.

## Migration

* **One new table, `todo_departures`,** created on boot like every other. No backfill.
* **No tool renamed or removed.** `upload_file` / `get_file` keep working unchanged.
* **Restart any long-running broker.** It serves `ui.html` and the briefings from its own
  copy, and the signing key is generated per boot.
* **Re-brief your agents** so they pick up `upload_url` and `leave_todo`.

## Tests

**1661 passing**, up from 1519.

Proven live: a **1 MB** file minted → curled up → listed → curled back, **SHA-256
identical**. Eight negative cases refused — expired, tampered signature, tampered content
type, upload-URL-on-read-route, read-URL-on-upload-route, neighbouring file id, wrong task,
revoked seat. **Key rotation proven across processes**: a second broker on the same db
rejects the first's URLs, confirming the key is per-boot and not derived from the database.

The departure headline builds the stuck state through real ops — three seats, a contract
one signature short, the third party never signing — asserts it stuck, removes the party,
then asserts the contract **locked with the original two signatures** and the rollup
advanced, **with no agent having acted**.

## Known and deliberate

* **Local mode has no honest signing story**, and none was invented. Loopback has no auth,
  so any local process can already POST. The signature there buys uniformity — same tool,
  same URL shape, same briefing sentence — not security, and `signing.py` says so.
* **An upload URL is single-purpose, not single-use.** One-shot semantics would need a nonce
  table, which is the schema change this design avoids.
* **Signed-upload failures return 401, not the token lane's 403.** A signature either
  verifies or it does not; reproducing 403 would leak which claim was wrong. Reads stay a
  deliberate 404, verified by value-equality against a genuinely missing file.
