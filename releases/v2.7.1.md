# sys-buddy v2.7.1 — 2026-08-06

Patch release. Three fixes, **one of them a correction to what v2.5.1 shipped**. No
schema change, no migration, no tool renamed or removed. Restart any long-running broker
to pick it up.

## Fixed

### Every mono chip on the dashboard was a fake bold

The stylesheet requested **Geist Mono at weights 400 and 500**. The dashboard uses it at
**600 in fourteen places and 700 in six**.

A weight that is not loaded gets **synthesised** — the browser smears the 500 to fake a
bold. That is why every mono chip (`wm`, `pc #N`, `@backend`, the event-log filters) read
as heavy and slightly blurry rather than crisp, and why it looked worst where it mattered
most: small text, light on dark.

Both `ui.html` and `gui_app.html` now request the weights they actually use. Verified in
a browser via `document.fonts.check` — all four resolve to real faces rather than
synthesised ones.

Worth noting the shape of this bug: nothing was broken, no test could have caught it, and
it degraded the surface a customer looks at for the entire life of the product. It was
found by someone looking at a screenshot.

### "Two agents. One contract." was stale in both halves

The desktop app opened with **"Two agents. One contract. Shipped."** Both halves had been
outrun by the product:

* **Casts have held more than two seats since v2.5.0** — `@backend-1`, `@backend-2`,
  `@frontend`, and the two-agent minimum counts seats rather than role types.
* **Contracts have been per-todo since v2.0.0.** A task with five todos has five
  contracts. "One contract" describes v1.

It now reads **"Their agents and yours. Agreed before built. Shipped."** — which also
states the thing that makes the enforcement architecture necessary rather than
decorative: this is collaboration **across organisations**, not one person orchestrating
their own agents.

The same assumption was hiding in three more places:

| where | was | why it mattered |
|---|---|---|
| the agent briefing | "sys-buddy is how **the two of you** coordinate" | **false** on any task with three seats — in the first sentence every agent reads |
| the dashboard, debug mode | "every issue needs **both parties** to say it is fixed" | **describes a rule the broker does not enforce** — v2.6.0 requires *every* party |
| two name hints | "how **your buddy** addresses you" | — |

The briefing now points at `roster()` rather than assuming a number.

**Singular is kept where it is still true.** You invite one person at a time, so "send
each person an invite link" is per-invite and correct. Not every plural is an
improvement.

### The file-size rule gets a number — correcting v2.5.1

v2.5.1 fixed a real problem: the briefings taught `upload_file`'s base64 argument as the
only way to share a file, three releases after the byte routes landed. The fix taught
*"use `upload_file` / `get_file` **ONLY if you cannot run a shell**"*.

**That overshot, and the overshoot cost more than the original bug.** An agent asked to
read a **37 KB** screenshot refused to call `get_file` — the charter had told it that was
expensive — and instead went hunting through config files for a bearer token to curl
with, then looped trying the tokens it found. Five permission prompts for its human, to
read something one tool call would have returned.

The warning was sized for a 328 KB screenshot (~128k tokens). The agent applied it to a
37 KB one (~15k tokens). **"Expensive" without a threshold is applied to everything.**

The rule is a number now, in every place it appears — the charter, all three briefings,
both tool docstrings on both surfaces, and the dashboard cheatsheet:

```
under ~100 KB     just call the tool. One call, no shell, no token to find.
                  ~15k tokens for a 37 KB file.
bigger, or        use the HTTP route. ~128k tokens for a 328 KB screenshot,
size unknown      and an 8 MB file will not fit in a context at all.
```

`list_files` already reports each file's size, so this is a **checkable** decision rather
than a judgement call — which is the difference between guidance an agent can follow and
guidance it has to interpret.

## Migration

* **None.** No schema change, no tool renamed or removed.
* **Restart any long-running broker** — it serves `ui.html`, `gui_app.html` and the
  briefings from its own copy.
* **Re-brief your agents** to pick up the size rule. An agent briefed before the restart
  still holds "only if you cannot run a shell".

## Tests

**1519 passing.** The test that pinned the old prohibition now asserts it is **gone** and
that a threshold is present, with both failure modes written into its docstring — the
under-correction that shipped before v2.5.1, and the over-correction that shipped in it.
A rule that has now been wrong in both directions deserves a test that names both.
