# sys-buddy v2.0.0 — 2026-08-01

Major release. **Five changes to agent-visible behaviour**, each one migrated, none
backwards-compatible on the wire — the task-level contract is gone, a session can hold any
cast of seats, a contract no longer has to describe an API, and the staging URL is host-owned
configuration rather than something agents negotiate. Everything from the unreleased 1.5
line ships here too: role tags, Slack that actually fires, and the dashboard work.

**Read `## Breaking changes` and `## Migration` before you upgrade.** Migration is automatic
and deletes nothing, but it renumbers contract versions — if you are mid-negotiation, land
your outstanding signatures first.

---

## Breaking changes

### 1 · One kind of contract: an agreement about ONE todo

The task-level contract is gone. A task is delivered by one or more todos, so "a contract on
the task" and "a contract on a todo" were two names for the same idea and two code paths for
every operation — and the second stayed reachable in ways nobody intended (a bare
`decline_contract` could kill a proposal on a deliverable the caller never named).

The word *contract* stays. Only the second kind is removed. The user-facing name is
**Todo Contract**.

- `contracts.todo_id` is now `NOT NULL`, and `UNIQUE(task_id, version)` is replaced by
  `UNIQUE(todo_id, version)` — versions are numbered per deliverable, so six todos each hold
  a v1. The two partial unique indexes this used to need collapse into one plain constraint,
  retiring the NULL-distinct trap that made partial indexes necessary in the first place.
- `propose_contract`, `lock_contract`, `decline_contract` and `reopen_negotiations`
  **require** `todo=N` in their tool signatures. `get_contract` and `report_status` stay
  optional on purpose: reading is how an agent recovers a number it lost, and bare `stuck`
  deliberately escalates the whole collaboration.
- A task with no todos has nothing to contract. The refusal points at `propose_todo`.

### 2 · Any cast — seats, not roles

`role` was doing two jobs at once, which is why a session of one backend and two frontends
was undescribable: the second frontend had to pair as `mobile` to get a seat at all.

It is now split in two:

| | what it is | |
|---|---|---|
| **`agents.handle`** | the **seat** | unique, stable — what signatures and party lists key on |
| **role type** | the **kind of work** | shared by many seats |

Two backends + two frontends + a QA is now describable, and the host can hold any role. Both
frontends must sign a todo that binds them — which falls out of quorum with **no logic
change**, because `roles_json` keeps its shape and only changes meaning.

Declaring 2+ seats of a type numbers them all (`frontend-1`, `frontend-2`) so no seat ever
holds the bare type string; on `add_seat` the shadowed seat gains a derived `<type>-1`
address. A role type therefore **always** means the type — it fans out for messages, and is
refused in a party list, where it would be ambiguous.

The dashboard gains a **roster**: every seat, its role type, and who holds it — including
seats nobody has joined yet, which is how an unaccepted invite becomes visible instead of
looking like a missing person.

### 3 · Names are unique per task

Enforced at join, in the same immediate transaction as the insert. Application-level rather
than a unique index, deliberately: a legacy database may already hold duplicates, and an
index would either fail the boot or force a retroactive rename on data the owner never agreed
to change.

Names stay **display-only and never a key**, so a rename can never move a signature. `/join`
and `sys-buddy join` now show the existing cast and the joiner's assigned seat *before* they
type a name, so the collision is prevented rather than reported.

Without this, "message Sarah" is ambiguous the moment a task holds a Sarah on backend and a
Sarah on frontend — and the mistake is silent.

### 4 · A contract is ≥1 named unit, not necessarily an API

A contract is a list of things with attributes that the parties agree on. It does not matter
whether those things are endpoints, types, screens or acceptance criteria — the invariant is
the same either way: *we said we would build it like this, and this is how we built it.*

| unit key | kind |
|---|---|
| `endpoints` | `http` |
| `types` | `schema` |
| `screens` | `ui` |
| `criteria` | `none` |

The unit key **names** the kind, so `interface_type` is inferred rather than declared —
requiring both is two chances to be wrong instead of none. Natural keys are kept per kind, so
every existing contract stays valid byte-for-byte with **no `spec_json` migration**.

`none` still requires `criteria`: the second half of the invariant has to be checkable, or
the contract is a wish.

Before this, only a backend could realistically propose, because the schema demanded an API
section. Two frontends agreeing on four screens had nothing to sign.

### 5 · staging_url is host-owned configuration

It used to live inside the signed spec, where it churned for reasons nobody negotiated
(tunnel URLs rotate on every restart) and was an **agent-controlled field on the most
security-sensitive value in the system**.

Now: `tasks.staging_url` with an optional per-todo override on `todos.staging_url`, resolved
live, host-set only, event-logged, with `contracts.staging_url_at_lock` recording what was
actually agreed at signing time.

- An agent-supplied `staging_url` inside a spec is **refused, not ignored**. Silently
  dropping it would let a prompt injection appear to succeed.
- It stays **withheld until every party has signed**, on the dashboard as well as the wire.
- Resolution is kind-agnostic on purpose: a `ui` contract is verified by opening the deployed
  app, so it needs the target most.

## Migration

Automatic on broker start. Verified repeatedly against copies of a real database: nothing
deleted, foreign keys clean, repeat boots byte-identical.

- **Existing task-level contracts are adopted, never deleted.** Each task's chain moves onto
  a NEW todo (`MAX(number)+1`) whose party list is the task's full cast — exactly who a
  task-level contract bound — and whose scope records where it came from. Signatures key on
  `contract_id`, so every one survives untouched. The `contracts` table is rebuilt once to
  make `todo_id` `NOT NULL`; the migration is re-entrant, deletes nothing, and rolls back
  whole on any failure.
- **Versions renumber.** Because versions are now per-todo, a task-level `v3` becomes `v2 on
  todo #1`. Nothing is lost, but a number quoted in a chat thread yesterday will not match.
  **Land any outstanding signatures before upgrading.**
- Added the missing `contracts.proposed_by` migration. A database old enough to predate todos
  may also predate that column, and the adoption reads it — without the `ALTER` the boot died
  on `no such column`, i.e. on exactly the databases the migration exists to rescue.
- **Restart any long-running broker.** A process started before this release keeps serving
  its old code against an unmigrated database.
- **Agents should re-run pre-flight** (`pf`) — the quiz gained a `notify` question and the
  `direct` question got harder.
- **Slack needs arming once per session** unless you export `SLACK_WEBHOOK_URL`. If you
  previously relied on `sys-buddy local` or the desktop app to notify, note that it never
  did — see `## Notes`.
- `roles_json` keeps storing canonical role names — role tags never reach storage.

## Added

### Role tags — BE / FE / MB / DE

A human types `sm @BE ship the token endpoint` to their own agent instead of spelling
`backend` out every time.

`service.py` gains `ROLE_TAGS` and `resolve_role(value, roles)`. Resolution runs in a
fixed order — **exact match → case-insensitive match → tag expansion** — and returns
`None` when nothing matches, so the caller raises its own error and this function never
decides policy. The ordering matters: a task that declares a real role literally named
`be` still wins over the tag, so a tag can never shadow a genuine role.

`post_message` resolves **before storing**, so `to_role` on the message row is always a
canonical role name. The delivery fan-out and the dashboard match on it exactly and must
never see `"BE"`.

Tags are handled at **both layers on purpose**: agents are briefed to expand them
(`rules.py` and both `onboarding.py` briefings), *and* the broker resolves them anyway —
so a tag that reaches the wire is delivered rather than rejected. That is the same
"broker enforces, agents request" split used everywhere else in the system.

A tag names a **role, never a person**, and only resolves against roles declared on this
task. Addressing a role the task does not have is an error, not a broadcast. And a tag a
**peer** writes inside a message is still DATA — it redirects nothing.

### The `designer` role on the dashboard

`RL` in `ui.html` only knew backend, frontend, mobile and broker, so a designer seat fell
back to a grey `D` avatar and read as an unknown role. Added `--role-designer`
(`#B8823C` light, `#D6A05E` dark), the matching `RL` entry, and the Tips legend now lists
four roles instead of three.

### The missing `upto` and `notify` shortcodes

`upto` (`share_activity`) shipped in 1.4.0 and was taught in `onboarding.py` — but never
made it into the dashboard's shortcodes cheatsheet. That is the same drift class as the
1.4.0 fix "cheatsheet missing todos": the panel is a hand-maintained mirror, and nothing
tied it to the prompt.

Both `upto` and the new `notify` are now on the cheatsheet, and the role-tag row is
**rendered from `ROLE_TAGS`** rather than hard-coded, so that list cannot drift again.
The tags live under Messaging rather than in a group of their own, because they are an
argument spelling, not a command — `sm @BE` *is* `sm @role`.

Also found while auditing: the **contract** briefing never taught `upto` at all — only
the debug briefing did. Both now carry it.

### Slack, wired up and provable

`notify_human` has existed since 1.0.0 and the broker already posts terminal lifecycle
transitions. What was missing was everything around it, so this release adds:

- **`validate_webhook(url)`** in `slack.py`, shared by every entry point (Host screen,
  CLI env var, notify) so they cannot disagree about what is acceptable. It requires
  `https` — task content must never leave in cleartext or over a non-web scheme — and is
  **deliberately not pinned to `hooks.slack.com`**, because self-hosted relays and test
  doubles are legitimate and baking a vendor hostname into a validator ages badly. https
  plus a real host is the security boundary; the rest is the operator's call.
- **`is_configured()`**, and a GUI bridge — `slack_status()`, `set_slack_webhook(url)`,
  `test_slack()`. The config object is process-global, so a host can arm Slack **mid-
  session without restarting the broker**.
- **A Slack field on the Host screen** (`type="password"`) with a **Send test message**
  button. A revoked, typo'd or wrong-workspace webhook is indistinguishable from a working
  one until something important fails to arrive — and `notify` is deliberately
  best-effort, so nothing else would ever surface the error. The test send is the host's
  proof. If `SLACK_WEBHOOK_URL` is exported the field says *"Active from
  SLACK_WEBHOOK_URL"*, so an empty box never reads as "off" over a working webhook.
- **A Slack chip in the dashboard header.** `viewer_block` gained `slack_active` — a
  **boolean**, never the URL, which is a bearer credential and does not cross to the
  browser. The chip renders only when Slack is armed; its absence means no Slack, which
  is the honest default and keeps the header quiet for the many tasks that never wire one
  up.
- **Training.** A charter paragraph in `rules.py`, `notify` in both briefings and on the
  cheatsheet, and a graded pre-flight question.

## Changed

### Your todo card tells you what happens next

A locked todo looked exactly like a stalled one. Nothing said the contract was waiting on
a signature, or that the producer had to report ready before anyone could test — so the
only way to know the next move was to have read the state machine. The author of this
project got stuck on it twice.

Every todo now carries a line naming **who owes the move, the shorthand to type, and
why** — and it narrows as facts arrive ("backend or frontend" becomes "frontend" once
backend signs). It is derived from the same predicates the writes enforce, never a second
copy of the rules, and two tests walk a todo start-to-finish doing only what the line says
and assert the broker accepts every call.

### Push back on a contract with `decline_contract`

A contract had `lock` and nothing else, so an unsigned proposal meant EITHER "I have read
it and object" OR "I have not looked yet" — indistinguishable to the broker, so
indistinguishable to everyone. Todos have had accept AND decline since they shipped;
contracts were the odd one out.

`decline_contract(reason, todo=N)` marks that version dead and carries the reason to the
thread and the event log. Signing it afterwards is refused with an error naming
`propose_contract`, because the answer is a new version. Anyone bound may decline,
including the proposer. Not a `reject`: nothing here terminates the todo — killing a
proposal is not killing agreed work.

### `ship #N` — propose and sign in one move

Humans think of "agree this and sign my side" as one action; the tools were two. `ship`
is shorthand only — no broker tool — and it signs YOUR side alone. It is also the answer
when someone says "sign" with nothing proposed: propose it under a stated assumption and
sign that, rather than stalling to ask.

### Commands and Workflows panels

The task view had grown four collapsed reference sections. Now that the todo card explains
itself in place, that material moved behind two header buttons: **Commands** (the shorthand
plus the real MCP tools) and **Workflows** (how a todo goes from idea to verified). Tips is
gone; its three legend items moved next to the `→ role` chips they explain.

### Pick your agent when you join

sys-buddy speaks standard MCP over HTTP, so any MCP client can connect — but onboarding
only ever offered one `claude mcp add` command, which is useless if you have no terminal.
The join page now asks which agent you use and renders instructions for **Claude
(terminal or desktop app), Cursor, Gemini CLI**, or a generic path for anything else.

Every instruction was verified end-to-end against a real broker rather than written from
documentation, and the findings are recorded in `docs/connect-your-agent.md`. Four
assumptions turned out to be wrong: "save this as `.mcp.json`" would have clobbered
existing servers, a full app restart is unnecessary, `/mcp reconnect` is CLI-only advice
that dead-ends in the desktop app, and the Directory is a published-connector catalogue
that will never list a self-hosted broker.

### Pre-flight gained a question, and one existing question got harder

**This is the agent-visible change.** Agents re-run pre-flight against a longer quiz:

- A new **`notify`** question: *which tool pings the humans on Slack, and when is it
  appropriate to use it?* Naming the tool is not enough to pass. The failure mode worth
  gating is an agent that pings on every step until the humans mute the channel, so the
  grader also requires evidence the agent knows it is for **terminal events** — verified
  or resolved, or stuck and needing a person.
- The **`direct`** question now also asks what `sm @BE` means, and grades on the
  *expansion* (`backend`), never on the tag itself.

### Slack notifications are session-only, and that is the decision

The webhook is **never persisted**. Not to the database, not to a config file.

Every credential sys-buddy stores is a **sha256 hash** — tokens are compared by hash and
never recovered. A webhook cannot work that way: it has to be **replayed verbatim** to
post anything. Storing it would therefore make it the first plaintext secret at rest in
the product, and it is a bearer credential with no expiry — anyone who reads that row can
post into the channel indefinitely.

So there are two non-database paths, both owned by the operator:

1. **Paste it on the Host screen** — it lives on the process config and dies with the
   process.
2. **Export `SLACK_WEBHOOK_URL`** — durable, in the operator's own environment, outside
   our storage.

The Host screen says so plainly ("Not stored: it lasts for this session…"), so nobody
discovers it by surprise on the next launch.

### Dev and test brokers bind `:9292`

`config.DEV_PORT` / `SYS_BUDDY_DEV_PORT` gives anything automated — Playwright runs,
seeded fixtures, throwaway brokers — a port of its own, off `DEFAULT_PORT`. A second
broker that tries to bind an in-use `8787` dies with `errno 48` **while its requests
quietly go to the broker already listening there**, which surfaces as a baffling auth or
data bug rather than a port collision. `CLAUDE.md` and `demo/README.md` (which had said
`8799`) are reconciled to the one value.

## Fixed

### The dashboard leaked an unsigned contract's staging_url

**Security.** `/api` emitted `staging_url` on contracts that were still unsigned, and
`pairing.py` issues every buddy a viewer token — so a party could read the target **without
signing for it**, which is the one thing signing is supposed to buy.

Found during a UI review, because one screen said *"stays hidden until every party has
signed"* directly above a card printing the target. `is_host` is now threaded through
`_task_detail` → `_todos_for` → `_contract_for`, and a non-host viewer sees nothing until the
contract locks. A regression test pins it, verified to fail with the fix reverted.

### Pre-flight froze whole sessions on one unready seat

The readiness gate was scoped to the **task**, so a seat that never passed pre-flight blocked
every write on it — including todos that seat had nothing to do with. Found live: a real
session was frozen because a third participant had not finished onboarding, and the two
people actually working could not proceed.

Pre-flight now gates the **interaction, not the task**. An unready seat blocks only the todos
it is party to. Two people do not need a third to have signed in.

### `host-viewer` and `invite` printed `:8787` whatever port you were on

`_cfg_from_args` never read `--port`, so both commands rendered URLs against `DEFAULT_PORT`.
On any other port the printed link simply did not work — and worse, on a machine already
running a broker on 8787 it pointed at the **wrong broker**, which reads as an auth bug.
`--port` is now accepted on both subcommands and flows through the shared config path.

### The next-step panel named a seat instead of a person

It said "frontend-1 to sign" where a human would say "Sarah". Seats are the right key
internally and the wrong thing to read on a dashboard. Joined seats are now substituted for
their holder's name, longest-first, leaving explicit `@handle` spellings alone.

### A signature on a todo contract did not move the dashboard

A signature landing on a todo's contract now moves the SSE detail token, so the dashboard
refreshes live on the moment that matters most. Every signature lands on a todo chain now,
and the task-level contract fingerprint saw none of them.

### Dashboard copy that taught the wrong thing

- The state chip said `contract locked` where the stepper and the task-list pill said
  `locked` — one state, two names, on one screen.
- The Workflows panel says **"contract"** in prose again. An earlier pass had substituted
  "the shape", which read as a different concept from the `propose_contract` /
  `lock_contract` tools sitting beside it, and taught neither.
- The **two-agreements** framing is promoted to the top of the todos panel. A real user read
  the old ordering and concluded that accepting a todo meant agreeing *how* to build it —
  accepting a todo agrees **what**; the contract agrees **how**.
- The task switcher renders as plain text when there is only one task, rather than offering
  a switch to nowhere.

### Nobody was briefed as producer unless a role was called "backend"

The broker has never hardcoded the producer — it derives it from whoever proposed the
currently locked contract, per todo. The agent-facing text never migrated, and branched on
`role == "backend"`. So a designer+frontend session matched NEITHER branch: both agents
were briefed as assessors, neither was told it could propose, and the two sat waiting for
each other while the broker was perfectly willing to let either start.

### The todo card showed the same fact twice

A todo carries two state fields — the agreement (`pending`/`accepted`/`contracted`) and
the march (`open`→`contract_proposed`→…). Both were rendered at once, so `contracted` sat
under a stepper reading "building": the same fact in two vocabularies. The march wins; the
chip now survives only where the march cannot express something (`pending`, `dropped`).

### The stepper labelled the phase that had just ended

`locked` sat as the current node for the entire time people were building, and `build` only
lit up once the producer was already live — i.e. once building was over. Now
`planning · building · ready · verified`, so locking advances to what the humans are
actually doing next.

### `ensure_local_identity` created duplicate agents

Symptom — a task showing the same agent twice, a phantom role in `roles_json`, and
pre-flight chips that no flow could ever clear.

Cause — the lookup matched on `role`, while the insert set `role = name`:

```python
"SELECT id, task_id, name, role FROM agents WHERE task_id = ? AND role = ?",
```

The docstring says "make sure the task and **this agent** exist" — identity here is the
**name**; the role merely defaults to it on first sight. So the moment an agent's role
differed from its name — reassigned on the task, or seeded and then corrected — the
lookup missed and inserted a **second agent with the same name**, appending that name to
`roles_json` as a role nobody had ever declared.

Fix — look up by `name`, and register the name-as-role **only when genuinely inserting**,
so re-seeing an existing agent can never grow `roles_json`. The function now returns the
agent's *current* role rather than its name. Three regression tests in
`tests/test_identity.py`.

This was not a seeding artifact. It is what produced the phantom pre-flight chips seen on
live task screens.

### `_contains` made short-needle readiness checks unfalsifiable

Symptom — a pre-flight question that every agent passes, gating nothing.

Cause — readiness grading is deliberately forgiving: case-insensitive **substring**
matching, because it has to find `to_role="backend"` inside a sentence. But forgiving has
a floor. Grading on a needle short enough to appear inside ordinary words — `"be"` also
matches *because* and *before*, `"ok"` matches *broken* — means the check can never fail.
This was hit while writing the role-tag question, where `"be"` is the obvious thing to
grade on and is exactly the wrong thing.

Fix — a new `_contains_word` matches on regex word boundaries, so `"be"` matches `be` and
`@BE` but never *because*. `_contains_any` now applies it automatically to any needle of
four characters or fewer, so a caller can pass a mixed bag like
`("stuck", "verified", "done")` without one weak entry silently disabling the whole check.
Both helpers carry docstrings saying which to use when, and the module docstring states
the floor. Three tests in `tests/test_readiness.py`, including one that pins the
*because* trap.

## Notes

**Why Slack looked broken:** `slack_webhook` was read in exactly one place — inside
`cmd_serve`. Both `sys-buddy local` and `sys-buddy gui` built their `Config` without it,
so `notify_human` returned "No Slack webhook configured" on the two on-ramps people
actually use, silently, no matter what was exported. `cli.py` now reads
`SLACK_WEBHOOK_URL` in `_cfg_from_args`, which every mode goes through, and
`gui.py:_run_broker` passes it into its own `Config`.

## Tests

**988 passing**, up from 669 at the start of this line.

Migrations are the risky part of a major, so they are verified against **copies of a real
database** rather than fixtures alone: nothing deleted, foreign keys clean, repeat boots
byte-identical. The dashboard changes were additionally proven live in Playwright against a
three-seat session — backend plus two frontends, with an unjoined QA seat — which is exactly
the cast that was undescribable before this release.
