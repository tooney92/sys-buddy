# sys-buddy v2.0.1 — 2026-08-01

Patch release. Four fixes, all found by reviewing the 2.0.0 UI while shooting demo assets
— which is to say: by looking at the release rather than at the tests. **No schema change
and no migration.** Restart any long-running broker to pick it up.

The first fix closes a hole in one of 2.0.0's own headline features. If you are running
2.0.0 with more than one buddy on a task, upgrade.

---

## Fixed

### A buddy could read the staging target without signing for it

**This is the one worth reading.**

2.0.0 made `staging_url` host-owned configuration and taught `_contract_for` to withhold
it until a version locks, for anyone who is not the host. **The todo row one key away from
it was not taught the same thing.** `/api` carried `staging_url` and
`staging_url_effective` on every todo regardless of signature, plus the task-wide
`staging_url` on the detail payload beside them.

Pairing hands every buddy a `viewer_token`. So a party who did not want to read the
contract could read the target off an *unsigned* deliverable through the same credential —
the exact bypass the contract block had just been fixed to close.

The old comment reasoned that "a viewer token is a human reading a dashboard" and left the
fields open. That stops holding the moment the neighbouring field decides the opposite:
two fields that disagree about who has earned the target mean the stricter one is
decoration.

Both now follow the block's rule — **host, or this deliverable has a locked contract**. The
task-wide value is **host-only**: a buddy reaches the target through a todo they signed,
and the task-wide one would release it before any signature at all.

Titles, scopes and party lists are withheld from nobody. Withholding the target is the
*incentive* to read what is being proposed, so the proposal itself has to stay readable.

**Scope of the exposure.** The dashboard never read these fields, so nothing renders
differently and no screen ever displayed it — this was reachable only by calling `/api`
directly, with a credential every buddy already holds (it is in their own dashboard URL).
Severity is bounded by what the value is: the withholding is an *incentive mechanism*, not
a confidentiality boundary, and a staging URL is not a credential. But the Commands panel
prints the guarantee verbatim — *"staging_url is withheld until every party has signed"* —
and it was not true.

### A screens contract announced itself as "(0 endpoints)"

The proposal message hardcoded its unit count to `spec["endpoints"]`, so every kind but
`http` announced itself as zero. A four-screen UI contract arrived at the reviewing agent
as:

> Proposed contract v1 on todo #2 (Dashboard shell + pages) **(0 endpoints)**.

That is the http vocabulary leaking into the kinds that exist precisely so http is not the
only option — and it reads as an *empty* contract on the surface that is the peer's only
prompt to go and look.

| kind | before | after |
|---|---|---|
| `http` | `2 endpoints` | `2 endpoints` |
| `ui` | `0 endpoints` | `4 screens` |
| `schema` | `0 endpoints` | `2 types` |
| `none` | `0 endpoints` | `2 criteria` |

The count and the noun both come from the spec now. `unit_key` is already the plural and
`unit_label` the singular, which also keeps `criteria` from being pluralised into
"criterions". The tests are parameterised over `contracts.KINDS`, so a **new** kind fails
until its announcement counts the right thing.

### The tasks list said "sign the shape of it"

`ui.html` carries a comment, 900 lines below the blurb, explaining that hiding the word
*contract* behind "the shape" made the panel and the tools read as two different concepts
and taught neither. An earlier pass acted on that in the Workflows panel and missed the
blurb — which is the **first prose a new viewer reads**.

It now says *"agree what to build, sign a contract for how, and ship"*, which is also the
two-agreements framing the rest of the panel teaches: accepting a todo agrees **what**, the
contract agrees **how**.

### The role legend contradicted the screen

The avatar-row tooltip enumerated `backend · frontend · mobile · designer` while a `qa`
avatar rendered directly beside it. Any cast makes an enumeration wrong the moment someone
adds a seat, so it states the two rules the row actually encodes instead: colour means role
type, and `×N` marks several seats of the same type.

## Migration

- **None.** No schema change, no new tables, no tool renames, no payload key added or
  removed — three fields that were always present now return `null` for a non-host viewer
  who has not signed.
- **Restart any long-running broker.** A process started before this release keeps serving
  its old code, so the `/api` gate is not applied no matter what the agents do.

## Tests

**995 passing**, up from 988. Every fix was verified to fail with itself reverted — for the
kinds bug that meant watching all five new tests report `(0 endpoints)`, and for the target
leak, watching both new tests hand a buddy the URL.

The three UI changes were proven live in Playwright against a seeded three-seat session:
one backend and two frontends, with an unjoined QA seat.
