# sys-buddy v2.10.0 — 2026-08-15

Minor release. **A non-technical person can now take part — with a message box, and no AI
of their own.** One new nullable column (`viewers.agent_id`), added on boot, and one new
HTTP surface (`POST /guest/message`). No agent-facing tool changed. Restart any
long-running broker: it serves `ui.html` from its own copy in memory.

## Added

### The Guest seat — joining without an agent

Every seat sys-buddy has ever had assumes a human with their **own AI agent** on `/mcp`.
Engagement mode extended accountability to the person paying for the work — but it still
seated that person as an ordinary agent, and a real non-technical owner will not install
Claude Code and wire up an MCP server. The one persona the product most wanted to reach
was the one it could not seat.

**Concierge mode** adds a **guest**: a non-technical human who joins through a browser
**message box**, and whose messages the builders' agents read like any other. She installs
nothing and never opens a terminal. The host provisions her in one command and hands her a
link:

```
sys-buddy task add-guest acme-site --name "Ada"
# → http://<broker>/ui?v=<token>   (share it like a password)
```

### How a guest writes without cracking the read-only dashboard

The dashboard is **read-only by charter** (D11): every `/api/*` route is GET, and an agent
token — never a viewer's — is the only thing that can write. A guest has no agent token and
sends from the browser, so she needs a way to write that does **not** hand that power to
every host and buddy who also holds a viewer token.

The seam is a single link between two rows the system already keeps:

* A guest is a **real `agents` seat** (`role="guest"`, auto-`ready`, and — deliberately —
  **no agent token at all**; she never calls `/mcp`).
* Her **viewer token is linked to that seat** through a new nullable `viewers.agent_id`.
  It is **NULL on every existing viewer**, which is exactly what keeps all of them
  read-only.
* A narrow **`POST /guest/message`** surface — its own module, *not* a write route under
  `/api/*` — resolves the same `sb_view` cookie the dashboard uses, then **refuses any
  viewer whose linked `agent_id` is NULL.** So the read-only posture holds for everyone but
  the guest, and the exception is one route rather than a crack in the whole surface.

Two things make the write safe rather than merely scoped. The message **identity is stamped
server-side** from the linked seat — never from the request — so provenance is unforgeable
and the thread attributes it correctly (`Ada @guest`). And the message **type is hard-coded
to `note`**, a new plain-conversational type on the send allow-list: a guest types words,
she does not choose a type, and she therefore **cannot forge a lifecycle event** like
`verified` or `stuck` from her browser. `note` is on `ALLOWED_SEND_TYPES` precisely so the
guest path goes through the same `assert_sendable` gate as everything else; it renders as
the neutral *message* chip in the thread.

### The box is its own card, above the contract

The message **thread** is for *reading* what was said; the guest's box is the one place to
*write*, so it renders as its own card in the side column above the contract, shown only to
a viewer the token marks as a guest. `is_guest` on the viewer block only decides whether to
*draw* the card — the write is authorised on the server, so a client that forged the flag
would draw a card whose Send button 403s.

### A guest takes standards from nobody

Like the owner, a guest does no gradeable work, so the `guest` role is **exempt from
guidelines and from pre-flight** — setting a guideline on it is refused with a message
saying why, and the assessment paths skip it. Nothing an audited party could write ever
lands in a guest's (nonexistent) agent context.

## Migration

* **One new nullable column, `viewers.agent_id`,** added by a plain `ALTER` on boot. It is
  NULL for every existing viewer — so every host and buddy stays exactly as read-only as
  before, byte-identical on the wire.
* **No agent-facing tool renamed, removed, or added.** Guests are provisioned host-side
  (`sys-buddy task add-guest`); builders' agents need **no re-briefing** — a guest's `note`
  arrives in the thread and in `check_messages` like any other message.
* **Restart any long-running broker.** `ui.html` is package data and the running process
  serves the copy it booted with, so an un-restarted broker shows no guest box.

## Tests

**1671 passing**, up from 1661.

New coverage pins the two halves of the guarantee: provisioning creates a ready, tokenless
guest seat with a viewer linked to it; the guest viewer builds a write identity while a
host or buddy viewer builds **none**; a revoked seat — and a host-scoped (all-tasks) viewer
even if it were somehow linked — is refused; the write lands stamped from the guest's seat
as a `note`. At the HTTP layer the route returns **201** for the guest, **403** for a host
viewer and for no credential, **400** for an empty body, and is registered POST-only.

Proven live in Playwright against a local broker: a guest opens her `?v=` link, sees the
box appear above the contract, sends *"can we make the header green?"*, and it lands in the
thread as **Ada · @guest** — while the **host viewer sees the message but no box.** The
HTTP checks were re-confirmed against the running broker (host→403, anon→403, guest→201,
`GET /api`→200). Checked in light and dark.

## Known and deliberate

* **Host-vouches, not independent representation.** This guest talks to the *host's*
  plain-speaking agent, which is right for a trusted collaborator (a partner, a teammate).
  It is **not** the posture for an arm's-length paying client auditing a stranger — that
  case still wants the client's *own* agent, and is out of scope here.
* **The dashboard is desktop-only**, and a guest inherits that gate — she opens her link on
  a laptop, not a phone. Reaching a non-technical guest on mobile is a later concern, not
  this release.
* **`note` renders as the neutral *message* chip**, not a new labelled type. A human's
  message carries no lifecycle meaning, and inventing a chip for it would teach the thread a
  word it does not need.
