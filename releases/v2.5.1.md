# sys-buddy v2.5.1 — 2026-08-06

Patch release. **The briefings were still teaching the expensive way to share a file,
three releases after the cheap one shipped.** No schema change, no migration, no tool
renamed or removed. Restart any long-running broker to pick it up.

## Fixed

### Two of four briefing surfaces never learned about the byte doors

v2.2.0 gave files their own door — `POST /files/{task_id}` and
`GET /files/{task_id}/{file_id}` — for one reason: `upload_file` carries the file as a
base64 **string argument**, so the agent has to *generate* the whole encoding token by
token. A 328 KB screenshot costs about **128,000 tokens**; the documented 8 MB cap was
unreachable through the only path that existed.

That release updated the tool docstrings and the debug-mode briefing. It did not update:

* **`RULES_OF_ENGAGEMENT`** — issued by the broker to both parties at pairing and served
  by the `rules` tool.
* the **contract / engagement onboarding block** — the briefing a host pastes into their
  agent to start work.

Both went on teaching `upload_file(name, content_base64, content_type)` as the **only**
way to share a file. So the two surfaces an agent is most certain to read were the two
still sending it down the path the release was written to replace. Both now lead with the
route and name the base64 pair as the no-shell fallback it is, with the token cost stated
so the choice is legible rather than arbitrary.

### The type list drifted again, in the same way, in a new place

Both stale briefings also spelled the accepted types by hand as *"PNG/JPG, PDF, or ZIP"* —
omitting `text/html`, which the broker had accepted since v2.2.0. This is the **identical
defect** v2.2.0 fixed in `upload_file`'s rejection message: a hand-written list that did
not learn about a type when it was added, so the broker described a type it accepted as
one that did not exist.

Fixed there and not anywhere else, so it grew back. Every surface that names the accepted
types now renders `files.types_sentence()`, generated from `ALLOWED_TYPES` with a
friendly-label map that falls back to the MIME string — a new type can render as
`image/avif` until somebody names it, but it can never silently vanish from a briefing.

`RULES_OF_ENGAGEMENT` became a `.replace()` on a template rather than an f-string: the
document carries a literal JSON example, and doubling those braces would put the escaping
burden on every future edit of what is mostly prose. Consumers still import a plain `str`.

### The dashboard said the same untrue thing, twice

* **`MCP_TOOLS`** listed only `upload_file` / `list_files` / `get_file`. It now leads with
  the two routes and labels the base64 pair as the fallback, with the cost named.
* **`SHORTCODES` had no Files group at all** — no `files`, no `upload`, no `getfile` —
  even though `onboarding.py` has taught all three shorthands, in both modes, for three
  releases. A human reading the cheatsheet could not find file sharing.

### A literal `<task-id>` was being eaten as an HTML tag

Found only by looking at the rendered page. `cmd()` interpolates a shortcode's `desc` as
**raw HTML** — it cannot `esc()` it, because the role-tags row builds `<b>` into its own
desc. So `/files/<task-id>` rendered as `/files/`, with the task id silently swallowed by
the parser.

The two panels in that file follow **opposite** conventions, which is the actual trap:
`MCP_TOOLS` escapes both of its fields, so a literal `<task-id>` is correct there;
`SHORTCODES` escapes `code` but not `desc`, so the same string must be written
`&lt;task-id&gt;`. That asymmetry is now documented on the field itself.

Worth stating: **pytest was green through this the entire time.** The tests assert the
table's contents, not what a browser makes of them.

## Migration

* **None.** No schema change, no new table, no tool renamed or removed, no payload key
  removed. The base64 path is untouched, so an agent already using `upload_file` /
  `get_file` keeps working — it is now taught as the fallback rather than the norm.
* **Restart any long-running broker.** A process started before this release keeps
  serving its old `ui.html` and keeps briefing agents from its old copy of the charter.
* **Re-brief your agents** to pick up the cheap routes. An agent briefed before the
  restart holds the old text in its context.

## Tests

**1434 passing**, up from 1432. Two new, both anti-drift:

* the route must appear **before** `upload_file` in the charter — an agent reads the first
  thing, so ordering is the behaviour;
* every entry in `ALLOWED_TYPES` must appear in **all four** briefings, so the list cannot
  fall behind in one place the way it just did in two.

Both dashboard panels driven in Playwright against a local broker on a throwaway database:
light and dark, and on a debug task, where Todo Contract and Todos drop out and Files
correctly stays. `uv build` was run as a dry run before the merge and the wheel checked to
confirm it carried the change.
