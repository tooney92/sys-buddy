# sys-buddy v2.17.0 — 2026-08-20

Minor release. **The host runs seat and token logistics from the dashboard now — reissue an
invite, extend a token, copy the task id — and the join screen walks a stuck buddy through the
two failures that actually cost sessions.** No schema change. **Restart any long-running broker**
so it serves the new `/host/*` routes and the new page.

Every one of tonight's changes came out of a real, painful evening: an invite that lapsed
mid-handoff, a `--task "<title>"` that got `unknown task`, an agent that connected as the wrong
seat, and a buddy who saw no tools and no reason why.

## Added

### Reissue or mint an invite for any seat — from the board

A host who sees an unfilled seat on the roster no longer drops to a terminal. Each seat carries
its own action: a **never-invited** seat gets **Invite**, a seat with a pending invite gets
**Reissue** (+ a one-click **Copy** of the join URL). Behind it, a host-only `POST /host/invite`
mints a fresh single-use invite and returns **both** link forms — the join URL a human opens and
the `sb1_` link an agent redeems — built from the host's own origin, so they point at the tunnel,
never at loopback. A guest seat is refused at the route (a guest joins through a dashboard link,
not an agent invite), not merely hidden in the UI.

### Extend or lift agent-token expiry — the 24h-trap recovery

A tunnelled broker gives agent tokens a 24h TTL, and when one lapses the agent cannot even
`rotate_token` (it authenticates with the token it is replacing) or `report_status("stuck")` — it
is locked out of the tools that could save it, and the failure reads as "revoked" when nothing was
revoked. **Extend +24h** and **Never expire** now sit under the Cast header (`POST
/host/extend-tokens`); only live seats are touched, so a revoked seat stays revoked, and the
result names exactly which seats moved.

### A copyable task-id chip

The board showed the human **title**, but every CLI command keys on the task **id** — so a host
who typed `--task "<title>"` got `unknown task`. The header now carries the real id as a mono chip
that copies on click. The one string every command needs is one tap away.

### A live invite countdown, and clearer seat states

A pending invite shows **"expires in MM:SS"**, counted down from the wall clock with no refetch,
flipping to a muted **"invite expired"** on its own the instant the window lapses. Each roster row
reads one plain state: *not invited* → **[Invite]**, *invited* → the countdown + **[Reissue]**,
*joined* → who took it.

### Copy-pasteable examples in the Commands panel

The panel is now a centered modal, and every command shows a worked **example** beneath its
abstract signature — `sys-buddy invite --task checkout-api --role mobile …` instead of only
`<TASK> <ROLE>`. The signatures still generate from the CLI so they can't drift; the examples are
one sanctioned, guarded set.

### Longer-lived invites

Single-use invites now live **30 minutes** (was 15) — long enough that a host who mints one, then
goes to explain the join to a teammate on another channel, comes back to a code that still works.

## Fixed

### The join screen now troubleshoots itself

Two collapsible blocks per client card, each rung earned by a real failure:

- **"Tools not showing?"** — the new-session / approval / **shadow** ladder. The one that bit
  hardest: a stale, same-named `sys-buddy` in a higher-precedence scope (local `~/.claude.json`)
  silently shadowing the working project entry, so the client connected to a dead broker.
- **"Connected as the wrong seat?"** — distinct from the above: the tools DO load, but you connect
  as a different token/seat than intended, because a client resolves its config from the folder it
  has open plus scope precedence. Called out for **VS Code** by name, where the opened workspace
  folder silently decides which config wins. The refrain on every card: **one seat = one token =
  one config; every client reads config by the folder it opened.**

### Review fixes shipped alongside

A high-effort review of the above caught four defects, all fixed here: the Commands modal's
backdrop `<div>` was left unclosed (it rendered only because it was the last fragment before
`innerHTML`); `POST /host/invite` didn't enforce the guest exclusion the UI hides; the
extend-tokens confirmation timer could clear a newer banner early; and `SPEC.md` still documented a
15-minute invite window the code no longer used.

## Migration

None — no schema, no config. **Restart any long-running broker** so it serves the new `/host/*`
routes (invite reissue, token extend) and the new dashboard page. An open dashboard just needs a
reload; the host actions appear only for the host's all-tasks viewer token, and the two new routes
`403` any other token — the board stays read-only for buddies and guests.

## Tests

**1740 passing**, up from 1703.

New coverage: `POST /host/invite` and `POST /host/extend-tokens` succeed for the host token and
**403** a buddy/guest/unknown token; a never-invited seat can be invited and a guest seat is
refused; the roster surfaces each pending invite's `invite_expires_at`; the Commands panel carries
exactly one sanctioned example map (the anti-drift guard still catches a renamed command); and
every join-screen card renders both the "Tools not showing?" and "Connected as the wrong seat?"
blocks — with the Claude CLI card carrying the `claude mcp list` / `claude mcp remove` diagnostics
and the Claude Desktop card carrying none (it has no `claude` on its PATH).
